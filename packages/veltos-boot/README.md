# veltos-boot

The VeltOS start-up experience.

| Piece | Installed to | Notes |
|---|---|---|
| Plymouth theme `veltos` | `/usr/share/plymouth/themes/veltos/` | Logo in the centre and a spinner of white dots below it on a near-black background, like Windows. Password prompt images (also used for the disk encryption password) are copied from Plymouth's `spinner` theme. |
| Plymouth defaults | `/usr/share/plymouth/plymouthd.defaults` (Plymouth's own file diverted to `plymouthd.defaults.debian`) | `Theme=veltos`. This file — not the `default.plymouth` alternative, which is also set — is what `plymouth-set-default-theme` and the initramfs hook read. Before this diversion the theme named there was not installed and every initramfs (also the live ISO's) fell back to the text splash. The initramfs is rebuilt via the `update-initramfs` trigger that `dh_installinitramfs` adds for the hook. |
| SDDM ordering | `/usr/lib/systemd/system/sddm.service.d/veltos-plymouth.conf` | `After=plymouth-quit.service`, as upstream SDDM's unit has it; without it automatic login of the live session sometimes failed (`sddm-helper` exit 63). |
| GRUB theme `veltos` | `/usr/share/grub/themes/veltos/` | For installed systems: logo and "VeltOS" on navy, menu below in Inter (converted with `grub-mkfont`), rounded highlight for the selected entry, thin countdown bar. |
| Boot defaults | `/etc/default/grub.d/veltos.cfg` | `GRUB_DISTRIBUTOR="VeltOS"`, `quiet splash`, theme, os-prober enabled so Windows is listed, menu hidden like on Windows (`GRUB_TIMEOUT_STYLE=hidden`, 2 s; Esc/F4/Shift shows it), fixed video mode `1024x768,800x600,auto` (plain `auto` made VirtualBox on Hyper-V stop the VM with a triple fault when Linux started — reproduced and fixed on a copy of the product owner's installed disk; the screen's own mode is put in front of it by `veltos_resolution.cfg`, see below) with `GRUB_GFXPAYLOAD_LINUX=keep`. `panic=10`: like Windows, the PC restarts by itself 10 s after a kernel panic or when the initramfs cannot find the system disk, instead of stopping; with veltos-recovery, GRUB counts these starts (next row). |
| GRUB entries | `/etc/grub.d/10_linux` (copied there by the postinst from `/usr/lib/veltos-boot/grub.d/`; Debian's script diverted to `/etc/grub.d/10_linux.dpkg-veltos`) | Runs Debian's script and renames "VeltOS GNU/Linux" to "VeltOS" and drops the "Loading Linux …" messages. Not shipped as a conffile: a conffile at a diverted conffile's path made dpkg stop with a question during the upgrade test. With veltos-recovery installed (its `veltos-recovery.target` exists), like Windows' Automatic Repair: every VeltOS entry except Debian's "(recovery mode)" runs `veltos_count_start`, which sets `veltos_failed` in GRUB's environment to 1, then 2 (veltos-recovery's `veltos-boot-ok.service` clears it once the sign-in screen is up); the first entry is copied as **VeltOS Recovery** (id `veltos-recovery`, `quiet splash nomodeset systemd.unit=veltos-recovery.target`, not counted and without `panic=10`) and **VeltOS (safe graphics)** (id `veltos-safe`, `nomodeset`, counted; Automatic Repair's Safe mode starts it once); when `veltos_failed` is 2 the default entry is VeltOS Recovery. Only where GRUB can write its environment file (`grub-probe`: not Btrfs/ZFS, no LVM, RAID or encrypted `/boot`), as with Debian's recordfail; elsewhere the entries stay as Debian's. |
| Start-up resolution | `/usr/libexec/veltos-boot/boot-resolution`, `/usr/libexec/veltos-boot/boot-resolution-sync`, `/usr/lib/systemd/user/veltos-boot-resolution.service` (in `plasma-workspace.target.wants`), `/usr/share/polkit-1/actions/org.veltos.boot.policy`; writes `/etc/default/grub.d/veltos_resolution.cfg` | The boot menu and the start-up screen at the screen's resolution instead of 1024x768 (product owner, 2026-10-22: the boot screen was small). `boot-resolution detect` reads the connected screen's preferred mode from the kernel's DRM connectors (the built-in panel first); the installer's `boot-resolution` job (calamares-settings-veltos) runs it and `boot-resolution set WxH --root TARGET`. `set` writes `GRUB_GFXMODE=WxH,1024x768,800x600,auto` (modes the firmware cannot show are skipped by GRUB) and runs `update-grub` (not with `--root`: the installer's bootloader jobs run it in the target afterwards); GRUB hands the mode on to Linux, so the Plymouth screen uses it too. The file sorts after `veltos.cfg` and before a user's `zz-local.cfg`. At sign-in, `boot-resolution-sync` (after 20 s, nice 19; not on the live medium) reads the primary screen's current mode from KScreen (`kscreen-doctor -j`) and, when it differs, runs `pkexec boot-resolution set` (polkit action `org.veltos.boot.resolution`: the active signed-in user without a password; the helper accepts only a screen mode and, through pkexec, no `--root`). Needs `pkexec` and `python3` (Depends) and `kscreen-doctor` (libkscreen-bin, Recommends). |
| Keyboard in the initramfs | `/etc/initramfs-tools/conf.d/veltos-keymap` | `KEYMAP=y`: the disk encryption password (asked by the boot screen, cryptsetup-initramfs) is typed with the layout chosen in the installer, not a US layout. |
| Password screen | `/usr/share/initramfs-tools/hooks/veltos-boot`, `/usr/lib/veltos-boot/unlock-texts` | For encrypted installs. The hook copies Inter (the theme's font) into the initramfs - Debian's plymouth hook copies only one fallback font and the prompt was drawn in a monospace face - and changes the *initramfs copy* of cryptsetup's shell functions: the prompt reads "Enter the password to unlock this PC", after a wrong password "The password is incorrect. Try again." (instead of "Please unlock disk luks-<uuid>:"), and cryptsetup's technical splash messages for a wrong password or a successful unlock are not shown. If cryptsetup changes the code this relies on, its own texts stay and the hook warns. The password box sits below the logo. Unlimited tries come from the installer (`crypttab-tries` job in calamares-settings-veltos). |
| Menu and text | `/etc/grub.d/35_veltos` | Draws GRUB's own text black on black and shows the menu for 5 s when os-prober finds other systems (dual boot). |
| Start screen and F6 | `/usr/libexec/veltos-boot/start-screen`, `/usr/share/veltos-boot/start-screen/`; writes `/boot/grub/veltos/start-hint.tga` and `start.tga` | No boot menu, as on Windows (product owner, 2026-10-23: the menu with VeltOS, Advanced options and Recovery appeared after installing; Debian shows it for 30 s after a start that did not finish). While GRUB waits (2 s) it shows the start screen: the boot splash's background and logo at the boot splash's place and, in the bottom right corner, a small key cap "F6" with "Recovery" / "Kurtarma" (the system's language from `/etc/default/locale`). F6 is the hotkey of "VeltOS Recovery" (Automatic Repair, like Windows' F8); GRUB 2.12 starts an entry's hotkey also during a hidden wait. `35_veltos` runs `start-screen` at update-grub with the first mode of `GRUB_GFXMODE` (the screen's own, `veltos_resolution.cfg`), then sets the picture with `background_image -m stretch` and `clear` (without it gfxterm did not paint the picture while waiting); every VeltOS entry puts the picture without the hint back before Linux loads (`veltos_start_screen`), so the hint does not stay on the screen. Run-length encoded TGA (GRUB's PNG reader once failed; a flat screen stays small); the logo and the hint are pre-rendered at build time (`tools/build-assets.py`, twice as large for 4K). Only with VeltOS Recovery (the same conditions as `10_linux`), and not in dual boot (the menu is shown there). After a start that did not finish the menu stays hidden too (`recordfail`); VeltOS' own count opens Automatic Repair after two. |

All images and fonts are generated at package build time by
`tools/build-assets.py` from `branding/veltos-logo.svg` (a copy of the
master logo in `veltos-desktop`; `tests/repo/test_consistency.py` keeps
them identical) and Debian's `fonts-inter`. The same script puts the
start-up resolution files from `resolution/` into the package tree.

GRUB font names: `grub-mkfont` names a font "<family> <Regular|Bold> <size>";
Inter's SemiBold file reports family "Inter" and style Regular, so it is
converted with the family name "Inter SemiBold" — themes refer to it as
"Inter SemiBold Regular 20". The build checks every name.

The live ISO's own boot menu is configured in
`build/live-build/config/bootloaders/`; `build/scripts/build-iso.sh` copies
this package's GRUB fonts and highlight images into it.

Tests: `tests/test_boot.py` (theme file, spinner animation loops, password
box below the logo, theme font copied by the hook, `unlock-texts` on an
excerpt of Debian's cryptsetup functions, Plymouth defaults, SDDM drop-in, diversion scripts, GRUB theme uses only generated
fonts, highlight slices, the kernel command line with `panic=10`; the
Automatic Repair entries made from a stand-in Debian script: counted
starts, Debian's recovery mode not counted, the VeltOS Recovery and safe
graphics entries, the default switch, no counting on Btrfs and none
without veltos-recovery; the resolution helper: the built-in panel
preferred, no mode without a screen, the mode written before the safe
ones, anything that is not a screen mode refused, no `--root` through
pkexec, the sign-in sync asking only when the mode changed, the polkit
defaults) and install-tree checks in `debian/rules`.
